# 能量乱斗 v4.3.2 房主性能诊断设计

## 1. 目标与范围

v4.3.2 是稳定性与诊断版本，不增加角色、地图或玩法模式。本版本解决的问题是：当玩家报告“延迟、抽搐、卡顿、操作黏滞或位置回拉”时，房主能够区分客户端掉帧、网络抖动、输入积压、位置预测偏差、断线重连和服务器步进超时，而不再只依赖服务端最终状态或主观描述。

本版本包含：

- 仅房主可见的实时性能诊断面板。
- 每秒一次的客户端聚合诊断上报。
- 当前对局的服务器诊断会话和赛后报告。
- 房主浏览器保存最近 10 局报告，并支持 JSON 导出。
- 设备、浏览器、网络类型和脱敏网络地址信息。
- 三张地图及电脑键盘、电脑鼠标、手机触控路径的针对性回归测试。

本版本不包含：

- 不向普通玩家 HUD 添加延迟、帧率或诊断文字。
- 不自动降低画质、特效、DPR、快照频率或输入频率。
- 不记录公网完整地址、浏览历史、账号信息、聊天内容或设备持久标识。
- 不永久保存服务器诊断文件。
- 不把诊断消息混入战斗快照或服务器权威规则。

## 2. 核心原则

### 2.1 诊断不能影响战斗

诊断使用独立 Socket.IO 事件，客户端以 `volatile` 方式每秒发送一次聚合数据。消息丢失、验证失败、房主页面关闭或浏览器存储失败都不得影响移动、射击、技能、地图碰撞、快照广播和胜负计算。

诊断不会改变现有 `performanceHint` 策略。项目继续保持最高画质、完整特效、完整 DPR 和现有 30Hz 默认快照策略。

### 2.2 数据必须可解释

面板中的指标使用玩家可理解的名称，但报告同时保存明确的工程定义。特别是“操作延迟”定义为：某条本地输入生成后，到包含该输入序号的服务器权威快照返回客户端所经历的时间。该值包含上行传输、服务器排队和处理、下行快照等待，不等同于纯网络 RTT。

浏览器无法可靠提供的信息必须显示为“未知”，不能根据屏幕尺寸猜测具体手机型号。iPhone 不支持标准网络类型 API 时，网络类型同样为“未知”。

### 2.3 房主专属与最小暴露

只有回环地址上的房主控制台，并且携带匹配的随机房主令牌，才能订阅实时诊断和接收报告。普通玩家 Socket 不接收任何其他玩家诊断数据。

服务器从 Socket 连接信息取得网络地址，在进入诊断状态前完成脱敏：

- IPv4 保留前三段，例如 `192.168.1.xxx`。
- IPv6 只保留网络前缀并标记 `/64`。
- 回环地址显示为“本机”。
- 报告和浏览器存储中不得出现原始完整地址。

实时面板可以显示玩家昵称以便现场定位；导出的 JSON 使用本局匿名别名 `P1` 至 `P6`，默认不写入昵称。

## 3. 方案选择

采用现有网络协议中的独立诊断模块：

1. 客户端在本地采集并按 1 秒窗口聚合。
2. 服务器验证、关联玩家、附加脱敏连接信息和服务器指标。
3. 服务器只将实时状态发送给已授权房主。
4. 对局结束后，服务器生成当前局报告并发送给房主。
5. 房主浏览器保存最近 10 局并提供 JSON 导出。

不建立独立端口或第二套服务，也不让房主直接连接每台玩家设备。这与现有六人局域网部署方式一致，减少开源用户的网络配置负担。

## 4. 模块边界

### 4.1 共享诊断协议

新增 `src/shared/diagnostics.ts`，集中定义：

- 诊断协议版本与固定阈值。
- 设备环境、客户端秒级样本、服务器秒级样本。
- 房主实时快照、异常事件和赛后报告。
- 数值范围、可空字段和异常类别。

`src/shared/protocol.ts` 只引用这些类型并声明事件，不承载聚合算法。

### 4.2 客户端采集器

新增 `src/client/diagnostics-collector.ts`，职责单一：

- 记录 Phaser 实际渲染帧间隔。
- 记录输入序号的生成时间和权威确认时间。
- 记录位置校正距离与硬校正次数。
- 记录连接、断线、重连和诊断 RTT。
- 每秒输出一个聚合样本并清空当前窗口。

采集器保存有限队列：输入时间映射最多保留 240 条，秒级窗口只保存计算百分位所需的当前样本。无界数组不得进入长时间对局。

`GameRenderer` 提供只读诊断出口或回调，将帧间隔和每次 reconciliation 的校正距离交给采集器。`MobileApp` 负责生命周期编排，不自行计算百分位。

### 4.3 设备与网络环境

新增 `src/client/device-profile.ts`，在玩家会话建立和重连后发送一次环境资料：

- 浏览器名称和主版本。
- 操作系统/平台类别。
- 浏览器实际暴露的设备型号文本；没有则为 `null`。
- 屏幕尺寸、DPR、触点数量。
- CPU 逻辑核心数和可用时的设备内存档位。
- 可用时的 `effectiveType`、`downlink`、浏览器估计 RTT 和省流模式。

网络类型允许在秒级样本中更新，因为设备可能从 Wi-Fi 切换到热点。所有字段均做长度和数值范围限制。

### 4.4 RTT 与操作延迟

诊断 RTT 使用单独的 `diagnosticsPing` 应答，每秒最多一次。客户端使用同一 `performance.now()` 时钟计算往返时间，不比较客户端和服务器的绝对时钟。

操作延迟通过输入序号计算：

1. 输入发出时记录 `seq -> performance.now()`。
2. 收到 `lastProcessedInput` 前进的权威快照时，确认所有不大于该序号的输入。
3. 用当前客户端单调时钟减去每条输入的生成时间。
4. 在当前 1 秒窗口计算 P50、P95 和最大值。

这样可以发现“RTT 正常但操作仍然黏滞”的输入积压，也避免跨设备时钟同步误差。

### 4.5 服务器诊断会话

新增 `src/server/diagnostics-session.ts`，每个服务器最多保留一个当前对局会话：

- 首次观察到新对局时创建不可复用的 `matchId`。
- 保存地图、模式、开始/结束时间和匿名玩家别名。
- 按玩家保存最近实时样本、秒级时间线、重连事件和异常计数。
- 每秒附加服务器步进 P95、最大值和固定循环达到追赶上限的次数。
- 对局正常结束、房主强制结束或重置时生成带结束原因的报告。
- 已结束报告保留到下一局开始，确保晚打开或刚重连的房主仍可获取。
- 下一局开始时替换服务器内的旧报告；永久历史只存在房主浏览器。

服务器验证每个诊断样本：

- Socket 必须映射到当前真人玩家席位。
- 样本必须属于当前 `matchId`。
- 每个 Socket 最快 750ms 接受一次。
- 数字必须有限并在协议规定范围内。
- 过大数组、过长字符串和未知字段不得进入报告。

### 4.6 房主订阅

新增房主诊断订阅事件。授权沿用房主神器的安全边界：

- 只接受回环地址。
- 必须携带正确房主令牌。
- 授权成功后 Socket 加入专用 `host-diagnostics` 房间。
- 实时快照与赛后报告只发送到该房间。
- 普通 `roomState`、`gameState` 和 `/api/info` 不包含诊断明细。

## 5. 指标与异常规则

### 5.1 客户端指标

每秒样本包含：

- `rttMs`: 最新诊断 RTT。
- `inputAckP50Ms`、`inputAckP95Ms`、`inputAckMaxMs`: 操作延迟。
- `frameP50Ms`、`frameP95Ms`、`frameMaxMs`: 实际游戏帧间隔。
- `correctionP95Px`、`correctionMaxPx`: 权威位置校正距离。
- `hardCorrections`: 本秒硬位置校正次数。
- `stalls`: 帧间隔超过 50ms 的次数。
- `pendingInputs`: 窗口结束时仍未确认的输入数量。
- `connected`、`reconnects`: 连接状态和本局重连次数。
- 当前浏览器可见的网络类型摘要。

### 5.2 服务器指标

每秒服务器样本包含：

- 模拟步进 P95 和最大耗时。
- 固定循环本秒执行步数。
- 达到单次最多 3 个追赶步的次数。
- 当前真人/机器人、弹丸和活动技能实体数量。
- 诊断样本接受数、丢弃数和原因计数。

### 5.3 固定异常阈值

- RTT 大于 `120ms`。
- 操作延迟 P95 大于 `100ms`。
- 单次位置校正大于 `30px`。
- 单帧间隔大于 `50ms`。
- 单次服务器步进大于 `16ms`。
- 发生断线、重连或固定循环追赶上限。

一个秒级窗口可以触发多个异常类别，但同一类别在同一玩家同一秒只计一次。面板显示最近异常和本局累计次数，报告保存异常发生的相对时间、地图和类别。

## 6. 房主界面

主机控制台在现有房间控制与席位区域下方新增全宽、可折叠的“性能诊断”区域。默认收起，不嵌套进现有卡片。

折叠标题显示：

- 当前状态：正常、注意或严重。
- 本局异常总数。
- 最近一次异常距今时间。

展开后的实时区域包含：

- 服务器摘要条：步进 P95/最大值、追赶上限、实体数量。
- 六席诊断表：玩家、设备/浏览器、网络/脱敏地址、RTT、操作延迟、帧 P95、校正最大值、卡顿、重连。
- 单元格使用正常、中等和严重三档颜色，不使用连续动画。
- 未上报、浏览器不支持或 AI 席位明确显示 `--`，不显示 `0`。

报告区域包含最近 10 局：

- 时间、地图、模式、时长和异常数。
- 展开查看玩家摘要和服务器摘要。
- 导出单局 JSON、导出全部 JSON、删除单局和清空历史。

桌面宽屏使用紧凑表格；900px 以下允许诊断表自身横向滚动，但不得造成整个页面水平溢出。诊断面板不得改变现有顶部状态栏和开始/结束按钮布局。

## 7. 浏览器报告存储

新增 `src/client/diagnostics-report-store.ts`：

- localStorage 键为 `energy-brawl.diagnostics-reports.v1`。
- 每份报告包含 `schemaVersion: 1` 和游戏版本。
- 写入前执行结构验证，读取时丢弃损坏项。
- 只保留最新 10 局，按结束时间倒序。
- 遇到存储配额失败时先淘汰最旧报告再重试一次。
- 再次失败则仅保留内存中的当前报告并在房主面板提示，不影响服务器和游戏。

导出使用浏览器 Blob 下载，文件名包含日期、地图和匿名 `matchId`。JSON 不包含房主令牌、重连令牌、原始 IP 或昵称。

## 8. 错误处理与降级

- 诊断消息丢失：实时表显示样本距今时间，超过 3 秒标记“数据中断”，不重发历史秒样本。
- RTT 请求超时：本秒 RTT 为 `null`，其他数据照常上报。
- 浏览器 API 不支持：对应字段为 `null` 和“未知”。
- 非法或过频上报：服务器静默丢弃并增加丢弃计数，不断开玩家。
- 未授权订阅：返回失败确认，不发送任何诊断历史。
- 房主页面重连：重新授权并获取当前实时状态及服务器当前保留的已结束报告。
- 对局被强制结束或重置：仍生成报告，`endReason` 区分正常、强制结束、重置和服务器关闭。
- 诊断内部异常：捕获并停止该诊断功能，不得传播到固定步进或战斗事件处理。

## 9. 性能预算

- 每位真人玩家最多每秒一条样本和一次轻量 RTT 应答。
- 单个样本序列化后目标小于 2KB。
- 六名玩家总诊断上行目标小于 12KB/s。
- 服务器诊断聚合 P95 小于 1ms，不改变 `SERVER_TICK_MS`。
- 8 分钟六人对局时间线应保持在 localStorage 可接受范围；报告存储前执行最大长度限制。
- UI 每秒最多更新一次，不因游戏 30Hz 快照重复重绘诊断表。

## 10. 测试策略

### 10.1 单元测试

- 秒级聚合的 P50、P95、最大值和窗口清空。
- 输入序号确认、乱序快照、重复确认和 240 条上限。
- RTT 超时和空样本。
- 固定阈值分类和同秒去重。
- 设备/浏览器解析与缺失 API。
- IPv4、IPv6、IPv4-mapped IPv6 和回环地址脱敏。
- 报告保存、10 局淘汰、损坏 JSON 和配额回退。
- JSON 导出中不存在令牌、昵称和原始地址。

### 10.2 网络与权限集成测试

- 六个玩家每秒上报，只有授权房主收到实时状态。
- 普通玩家和错误令牌无法订阅。
- 过频、非有限值、错误 `matchId` 和超大字段被丢弃。
- 断线由机器人接管、重连回原席位后诊断时间线连续且重连数增加。
- 房主在赛后重连仍可取得服务器保留的当前报告。
- 下一局开始替换服务器旧报告，但房主浏览器历史仍保留。

### 10.3 玩家路径测试

三张地图分别覆盖：

- 电脑键盘持续贴墙、斜向滑墙和墙角脱困。
- 电脑鼠标瞄准、鼠标技能和自定义键位同时工作。
- 手机移动摇杆、攻击摇杆和位移技能摇杆。
- 客户端预测与服务器权威碰撞一致，不出现持续校正峰值。
- 模拟 40ms、120ms、250ms 延迟，抖动、丢包和短暂断线时，诊断分类与玩家现象一致。

### 10.4 浏览器与视觉验收

- 房主控制台在 `2048x1208`、`1024x800` 下无布局溢出。
- iPhone 横屏近似 `932x430`、常见 Android 横屏和 iPad 横屏不出现诊断 HUD。
- 面板默认收起、异常徽标可见、展开表格可读、最近 10 局和导出按钮可操作。
- 页面、画布和控制台无错误或警告。

### 10.5 压力与发布门禁

- 三张地图乘三种团队模式的六人 60 秒压力测试继续保持零墙体违规。
- 新增六客户端每秒诊断上报压力测试，验证带宽、服务器聚合耗时和内存上限。
- 完整 Vitest、类型检查、生产构建、地图视觉冒烟和干净克隆冒烟必须通过。

## 11. 完成标准

v4.3.2 只有在以下条件全部满足后才可发布：

1. 普通玩家无法接收任何诊断数据，房主令牌和原始网络地址不会进入报告。
2. 六名玩家持续上报不会改变战斗快照频率、输入频率、画质或特效。
3. 实时面板能区分网络、操作延迟、客户端帧、位置校正、重连和服务器步进问题。
4. 赛后报告可在房主浏览器保留最近 10 局并导出有效 JSON。
5. 三张地图及电脑/手机输入路径的预测和碰撞回归通过。
6. 完整自动化、压力、构建和浏览器验收全部通过。
